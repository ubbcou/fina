# 代码审查技能

## 使用场景

- 用户明确要求代码审查
- 用户询问代码是否有问题
- 用户请求代码质量检查
- 用户需要代码改进建议

## 审查标准

### 1. 代码质量

- **可读性**: 变量命名是否清晰，代码结构是否易懂
- **简洁性**: 是否有冗余代码，是否可以简化
- **一致性**: 代码风格是否统一

### 2. 最佳实践

- **TypeScript/JavaScript**:
  - 使用 TypeScript 类型注解
  - 避免 `any` 类型
  - 使用现代 ES6+ 语法
  - 适当的错误处理
- **React**:
  - 使用函数组件和 Hooks
  - 避免不必要的重渲染
  - 正确使用 useEffect 依赖
  - 组件职责单一

### 3. 性能考虑

- 避免不必要的计算
- 使用 useMemo/useCallback 优化
- 图片优化（Next.js 使用 Image 组件）
- 避免内存泄漏

### 4. 安全性

- 输入验证
- XSS 防护
- 敏感信息不要硬编码

### 5. 可维护性

- 适当的注释
- 模块化设计
- 避免过度抽象

## 审查流程

1. **理解上下文**: 先了解代码的目的和功能
2. **逐项检查**: 按照上述标准逐项审查
3. **提供建议**: 给出具体、可操作的改进建议
4. **优先级排序**: 区分关键问题和优化建议

## 输出格式

审查结果应该包含：

- ✅ **做得好的地方**
- ⚠️ **需要改进的地方**（按优先级排序）
- 💡 **优化建议**（可选）
